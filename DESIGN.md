# UJverse: a clear student starting point

The Start page explains its purpose immediately: faculty announcements, registration windows and university events. The main tasks share two distinct neutral surfaces: asking Versuś and browsing one information category at a time. The original UJverse logo, system font and light/dark/UJ colour tokens are preserved.

The assistant uses a compact identity header with a 96 px pixel mascot, a public-access label and one short description. The labelled question field is the focal point. Its send action and optional example questions form a clear action area; on phones sending comes before secondary examples. The existing public conversation flow, request handoff and account boundaries remain intact.

Faculty selection stays in a visibly labelled sticky strip. The current scope and choose/change action are readable. A searchable dialog supports full names and abbreviations, an explicit all-university option, selected state, empty search and keyboard focus. The strip reserves the same height as before, including in the chat layout.

The information surface preserves URL category selection, two bounded previews, catalogue links, source links and independent loading/error/empty/stale states. Saved items and customisation remain available. A coherent footer groups university services and UJverse tools, explains account requirements and keeps the project notice and expandable freshness information together.

The original pixel mascot has seven activities connected to real interaction and response phases. Full-body and face assets respect system and app motion preferences. Details: [pixel mascot notes](docs/design/versus-pixel.md).

The current refinement follows `interface-design`, `better-layout` and `better-ui` from the public UI Skills catalogue. Exact source links, the unavailable MCP connection and applied decisions are recorded in [UI Skills refinement](docs/design/ui-skills-refinement.md). No new palette, font, gradients or decorative shadows are introduced. Automated test suites are intentionally not run for this visual iteration, as requested.
