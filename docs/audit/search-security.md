# Search security review

Review recorded 12 November 2026 for the `codex/audit-2026-11-11` release. This is source and synthetic-fixture evidence; it is not a production deployment or a signed-in production authorization test.

## Implemented boundary

- Browser search no longer constructs a Meilisearch client or reads its index-wide credentials. Public information uses the normal Supabase anon/session client; account search uses the session client. Supabase verifies the JWT and applies database RLS independently of client session guards and chosen cohort IDs.
- User search requests explicitly searchable, unbanned profiles. Mapping also rejects hidden/banned profiles and suppresses departments unless their visibility flag is explicitly true. Post and Aula search use an inner author join and exclude banned authors before pagination, with defensive mapping as well.
- Every Aula message read specifies its cohort and excludes deleted messages. Filename search joins the parent message and filters that parent's cohort. Only positive safe-integer IDs enter the combined content filter. Message limits are capped at 50, offsets at 10,000, attachment matches and channel discovery at 100, and embedded filenames at 20 per message. Channel-kind discovery also specifies the cohort. Invalid wildcard-only queries issue no read; unrepresentable date filters return no messages.
- The authenticated `find_user` chat tool applies discoverability and ban filters before its scan limit and defensively filters results. It honors department visibility, rejects guest executor calls, and uses the same safe LIKE pattern helper. Explicit `ttlMs: 0` bypasses the shared tool cache for this lookup; other tools keep their existing defaults. Organic full chat responses remain user-scoped with their existing 30-second cache, and previously displayed conversation content is not retroactively removed.
- The Vercel synchronization handler authenticates webhooks, defaults to a successful no-op for database-primary search, and never exports posts, profiles, messages or attachments, including when its optional public mirror is enabled. That mirror handles announcements only and refuses the three old mixed/private index names. The changed Supabase Edge Function source is authenticated and acknowledges retired synchronization without exporting rows. A read-only production request to `functions/v1/sync-search` returned HTTP 404 with `NOT_FOUND` (requested function not found), so this legacy function is not installed in the configured project and needs no rollout there. A Vercel release does not deploy Supabase functions. Production `SEARCH_INDEX_SYNC_ENABLED` is absent, so the optional public mirror is off.
- All legacy private-index maintenance entrypoints are retired: `force-resync.ts`, `backfill-search.ts`, `sync-listener.ts`, `resync-search-final.ts` and `check-meili-tags.ts`. They perform no database or index reads/writes. This closes the remaining service-role exporter and removes advice to recreate the old private index.

## Outstanding operational evidence

The configured former Meilisearch host returned `404 Application not found` to the primary agent's read-only health/key-management probes. No private index was queried. Removing credentials from current code cannot revoke keys already distributed in old browser bundles; provider-side revocation or proof that the old application no longer exists remains an operational action. Optional public mirroring should remain disabled until a separate public-only index and restricted credentials are verified.

Anonymous production probes confirmed public-source reads and no visible non-USOS registration/Aula/timetable/notification rows where administrative counts established data exists. These probes do not establish exact deployed policy definitions, authenticated cross-cohort denial, historical-key revocation or production write denial. Those claims require authorized fixture accounts and/or the deployed policy catalog. Never query unrelated students' content to obtain that evidence.

`is_searchable` and `show_department` are search/display preferences, not general database column confidentiality: the existing authenticated profile SELECT policy is permissive. Search honors those preferences, but broader field privacy would require a separately scoped view/RPC and application migration.

The additive `20261112120000_aula_scope_integrity.sql` migration and disposable `scripts/aula-security-check/run.sh` fixture runner address the write invariants discovered in this review: a supplied attachment cohort must match its parent; messages/channels cannot move between cohorts; mutation access requires current membership; parent/channel links must remain within the message cohort. The disposable runner passed all nine assertion groups on PostgreSQL 17.11 with the original Aula migrations and the new migration applied twice. The final migration has an explicit transaction wrapper. Checks include both cohort directions, member/departed-member mutations, forged attachment metadata and preserved service-role maintenance; privileged callers must still keep relationships within their original cohort. These isolated results do not prove the production policy catalog. On 12 November the user confirmed that this exact migration completed without errors in Supabase SQL Editor. The agent did not perform remote DDL or independently inspect the deployed policy catalog.
