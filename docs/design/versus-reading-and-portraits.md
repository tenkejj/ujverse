# Versuś: clean outline, reading rhythm and portraits

This revision follows the user's screenshots of the light, dark and UJ themes. The pixel artwork itself is unchanged. Analysis of PNG/GIF/WebP frames found binary alpha and connected silhouettes; browser comparisons at 184, 192 and 200 px found no pixels outside the light-theme silhouette. The perceived stray edges came from the theme gamma filter lifting the near-black contour. Zero-intercept linear colour transforms now preserve a dark contour and gold glasses while providing a modest theme tint. Dark uses 1.25 per RGB channel; UJ uses 1.1/1.25/1.5. There is no blur, shadow, outline expansion or alpha-mask rewrite.

The homepage introduction is now bounded to 880 px and split into a character/heading row above a full-width, three-line question field. This increases its vertical presence and removes the very wide, shallow banner proportion. Existing example questions, submission semantics, IME handling and one-time chat navigation remain. The main sprite renders at 192 px on desktop (an integer 2× scale of its 96 px source), with smaller responsive sizes. The model/provider label is visible in the homepage, full-chat identity and mobile sheet: GPT-OSS · Groq. The current server configuration uses the existing GPT-OSS 120B/20B routing defaults; no models or provider settings changed.

The presentation cadence is shared between the renderer and send hook: 50 ms frames, nominal 60 characters per second, with adaptive catch-up capped to a requested 2.2-second presentation window. Word boundaries no longer extend forward by up to twelve characters every frame, which had made the former rate much faster than its nominal setting. Large bursts can still display faster to avoid a long tail after receipt. These are text-presentation timings, not measured model tokens per second. Stop, abort, unmount, conversation reset and system/app reduced motion immediately flush already-received text. Live OS motion preference changes use a direct media-query subscription.

Eight generic thinking phrases rotate every 2.8 seconds while no content is visible. Actual tool labels take priority and do not rotate. Screen readers receive a stable status rather than eight repeated announcements. The phrases do not claim a tool was used, a source was checked, or that completion is imminent.

A native disclosure below the question field opens three local small-portrait choices: Spokojny (idle), Ciekawski (listening pose) and Zaczytany (thinking pose). Native radios retain keyboard semantics. The validated `versusPortrait` preference is backwards-compatible with existing saved preferences and resets to classic. Only resting small portraits use that selection; active thinking/answering/greeting/error states retain their meaningful artwork. The alternate resting portraits use static PNGs so a decorative bookish look does not loop a busy animation. The choice persists across reloads and contains no account data.

Verification: app TypeScript compilation/build, code review and manual browser previews, without automated suites or model calls. Combined homepage previews covered all three themes at 1440 px and mobile widths 390/320, with no observed horizontal overflow. The choice changed the small navigation portrait and persisted after reload. The chat at 320 px shows the model label. Intercepted ready-reply previews showed 123 characters revealing over about 2.2 seconds, immediate stop/flush and immediate reduced-motion completion. Generic thinking rotated, actual tool labels stayed fixed, and a live OS motion change stopped rotation. These are bounded UI observations, not a user study or inference benchmark.

Existing build diagnostics remain: the large frontend bundle warning and Vercel's nonfatal `notificationHelpers.ts` Supabase relation-type diagnostic. This revision does not alter the backend, public data, authentication or original UJverse logo.
