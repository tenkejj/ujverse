# Versuś: explanation, expressions and efficient replies

The homepage now explicitly introduces an AI assistant. “O Versusiu” explains the default GPT-OSS 20B/120B routing on Groq, university information sources, response preparation, signed-in account access, what a model request may contain and freshness/quota limitations. Six short definition groups use the existing theme and small semantic icons. The main scene retains one focus. Its fixed desktop minimum now belongs to the conversation core, so opening the explanation leaves the summary in place and expands content below it. At narrow widths the explanation becomes one column.

The portrait chooser and its preference have been removed. Old saved preference objects remain readable; other settings are preserved. Small completed-message portraits use a stable hash of the message id to select a calm, curious or thoughtful face from existing assets. Thinking, answering, success and error take priority for the current turn. There are no additional decorative timers, new artwork or changes to pixel palette/alpha. Live system/app reduced motion still selects static assets.

The compact server persona now asks for an answer, useful context and at most one relevant next step. It avoids report-like openings, forced slang and repeated closings. Common announcement, registration, official-event and timetable results have conversational deterministic formatting. These results do not require a second model call to paraphrase known facts; an unrecognised question may still need a model for tool selection. Greetings, capabilities, identity, configured-model and method questions have zero-inference replies.

A complete, valid, single-day saved timetable can begin with a count and first/last time. Two or three classes are short paragraphs; larger sets remain scannable lists. Partial, invalid, multi-day or cancellation-marked data never receive an inferred day-end summary. An empty saved plan does not prove a free day. Timetable display, model clock and the fast-path ranges for today/tomorrow/seven days use Europe/Warsaw. Civil-day boundaries handle 23/25-hour DST days; response/prewarm cache keys include the Warsaw date to avoid yesterday's relative answer surviving midnight. Cancellation notices remain qualified because a lecturer-wide notice may not apply to every occurrence.

Economy changes preserve output budgets and low reasoning effort. The server keeps at most eight history messages and normally 6000 content characters. The full latest question is preserved up to the existing 16000-character API limit, even if it exceeds that soft budget. The newest retained assistant answer is capped at 3000 characters and older ones at 240, with an explicit omission marker and a boundary cut where possible. This is a character budget, not a tokenizer or an assurance that every request fits an account's quota.

Groq 429 responses are not retried within the same turn. Retry-After is retained for the wait message; transient transport/5xx failures keep bounded retries. A 413 gives explicit shorter-input guidance. When source facts are available and a synthesis stream fails before text, the fallback formats those facts locally without another inference call or caching an error. Optional background memory extraction now requires `VERSUS_MEMORY_EXTRACTION=1`; existing profile, plan and previously stored memory access remain. Optional smart-chip generation was already off by default. Response cache v5 invalidates older wording and remains scoped to user/context; prewarm uses the same key builder.

Production model overrides were absent when inspected: defaults remain `openai/gpt-oss-120b` and `openai/gpt-oss-20b`. No provider plan, billing setting, quota or model configuration was changed. Published Groq free-plan limits are account/model constraints; these changes reduce unnecessary calls rather than promise unlimited access. References checked on 10 November 2026: [rate limits](https://console.groq.com/docs/rate-limits), [reasoning](https://console.groq.com/docs/reasoning), [prompt caching](https://console.groq.com/docs/prompt-caching). Identical static prefixes and existing caching remain; no extra padding is added to chase cache hits.

Verification: browser previews at 1440, 720, 390 and 320 px, light/dark/UJ themes, six readable explanation groups with no portrait radios and no horizontal overflow. The disclosure summary stayed at the same coordinates when opened. Injected local conversation state showed distinct stable resting faces and thinking/answering/success/error poses; the 320 px composer stayed visible and a live motion change switched WebP to PNG. Synthetic timetable/cancellation/empty-result/registration/model-question examples were generated offline. Budget observations retained the latest 16000-character question, reduced a deliberately long example history and showed one attempt for a synthetic 429 versus two for a synthetic recoverable 503. Client system text did not replace the server persona; the observation made zero network calls. No automated test suites, real personal-data sessions or Groq inference calls were used. Model-generated tone and actual provider quota usage were not measured.

Offline date observations cover normal and spring/autumn DST boundaries, 23/24/25-hour days, seven-day ranges of 167/168/169 hours and cache rollover at Warsaw midnight. Build verification includes frontend compilation and the Vercel production build. The existing `notificationHelpers.ts` Supabase join-type diagnostic and large frontend chunk warning remain outside this revision.
