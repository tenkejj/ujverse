# Versuś: creature, conversation and logo refinement

This iteration preserves the original logo asset, system font and all existing themes. It applies the previously fetched MCP UI Skills (`interface-design`, `better-layout`, `better-ui`), plus a React rendering review. No new UI library, provider, model or dependency was introduced.

The header uses the original PNG through an SVG alpha mask with the artwork's actual bounds (526×591 inside its 728×1372 transparent canvas). `preserveAspectRatio` keeps the mark intact inside fixed, non-shrinking 40×44 / 44×48 boxes. The visible button remains centred on the viewport. Visual inspection covered 320, 390, 768, 1024 and 1440 px.

Versuś is now an original slender, angular creature inspired by expressive monster-collecting game characters: tall ear fins, cream muzzle, intelligent almond eyes, a book and a curved tail with a gold tip. The rounded human scholar and round glasses were replaced. Generated artwork was assembled into shared-palette 96×96 pixel sprites. The existing seven activity states, one-shot 3.6-second cycles, neutral ending poses, face variants and system/app reduced-motion PNG fallbacks remain.

The chat no longer opens a slash-command menu or routes slash shortcuts. Natural question suggestions remain. The composer uses 16 px text, composition-safe Enter handling and auto-growing height on the full chat. A truthful tool status replaces randomly rotating phrases. New messages use short transitions; Markdown paragraphs no longer animate independently. Received deltas are grouped into 40 ms rendering batches without character-by-character or punctuation delays. Completion/cancellation immediately exposes all text already received. Memoized Markdown avoids reparsing unchanged history. Bottom anchoring now belongs to the shared message list, including when the full chat uses an outer scroller.

Server replies use a shorter, warm and factual Polish persona. Destructive regex rewriting was removed: it previously collapsed Markdown newlines and stripped uncertainty/source phrases. Fact list headings and capability/greeting replies no longer force slang or advertise commands. USOS facts now read `title`, `opens_at`, `closes_at` and `registration_url`; official events read `date` and `event_url`. The earlier USOS field mismatch produced repeated “rejestracja — start bez daty”. Links are restricted to HTTP(S) and escaped when included in these fact lines. Empty catalogues are described as missing results, rather than proof that nothing exists.

Consumption changes: routing instructions decreased from 977 to 668 characters; synthesis instructions from 1,405 to 528. These are character counts, not token or money estimates. The browser sends the latest eight user/assistant messages while preserving full visible history. A single already-formatted fact up to 600 characters, with a hint up to 240, can skip the synthesis call. Ready replies are sent immediately instead of synthetic 80-character/50 ms chunks. Provider requests accept abort signals; cancelling synthesis or reaching its deadline closes the provider reader, skips incomplete-response caching and stops retries for abort/timeout errors. Existing authentication, public tool restrictions, scoped cache keys, TTLs and rate limits remain; the response namespace changes to v3 to avoid serving the old voice.

Verification follows the user's request to skip automated suites. Frontend production compilation/build passes. Desktop/mobile visual previews include empty, thinking, answering and completed chat states, the original logo, and the reduced-motion PNG source. Three bounded anonymous production requests were recorded before changes and the same questions were sent through the modified local handler using the configured provider. They confirmed readable Markdown and the new capability reply. Local USOS returned an honest empty result; it did not establish availability of future registrations. No authenticated/private account data was exercised. Render-state previews use browser memory and are separate from the real provider probes. Latencies from different deployments/cache states are not a controlled benchmark. No percentage cost reduction is claimed. Cache/KV variables were unavailable in the local probe; the existing fail-open behavior continued.

The API-wide strict TypeScript check also reports pre-existing issues in `notificationHelpers.ts` (Supabase relation shape) and `userMemory.ts` (nullable content). These unrelated modules are unchanged. Vercel's function builder reports the former non-fatally; the frontend retains its pre-existing large-bundle warning. This iteration does not claim a clean repository-wide type audit or a usability study.
